# MEFRION セキュリティ運用

公開先: https://mefrion.vercel.app/console/security

2026-10-26。Vercel上の運営専用画面とサイト側の収集処理、既存Supabase内の非公開記録・集計、11本のEdge Functionの観測を配備した。収集は運営画面へのログインと無関係に動作する。有料契約や新しい長期認証キーは追加していない。

## 閲覧を始める

運営用メールアドレスでログインし、このMEFRION運営画面用の認証アプリで二段階認証する。Supabase管理画面用の認証アプリとは別の登録である。確認コードや設定キーをチャットへ送らない。

現時点で運営者本人のTOTP確認が未完了のため、運営権限も有効化していない。本人が完了した後、確認済みの所有者IDに対して既存の `mefrion_set_operator` をサービス権限で実行し、期限90日以内のmoderator権限を付与する。本人確認前に権限を作る、MFAを省く、ブラウザから運営権限を自分で発行する仕組みは設けていない。権限更新も本人・有効なMFAを確認して行う。

## 画面の使い方

- **概要:** 24時間・7日・30日の時間帯別集計、検知の内訳、対象、繰り返し観測した仮名化接続元。未対応インシデントは全期間の件数。概要は任意で30秒ごとに更新する。
- **検知ログ:** 種類・重要度・記録元で絞り込み、1ページ50件、続きを読み込める。詳細には応答コード、記録時刻、正規化した対象、地域参考情報、照合用リクエストIDを表示。CSVは現在の条件から最大1,000件。CSVの数式注入を防ぐエスケープを行う。
- **インシデント:** 同じ仮名化接続元の5分間10件以上の対象シグナルをまとめる。50件以上は高、10件以上は中。サーバーエラーは別にまとめる。未対応・確認中・対応済み、400文字までのメモ、同時更新の競合検出、変更の監査記録を備える。編集途中のメモはメモリーに保持し、ログアウト時に破棄する。
- **監視範囲:** 記録元ごとの最近の受信、送信失敗の報告、詳細保存上限による省略を確認する。通信がない場合も受信は古くなるため、それだけで故障とは断定しない。

401/403/404/405/429や一般的なサーバーエラーは、攻撃成功の証拠ではない。404をすべて攻撃と数えない。攻撃の疑いは秘密ファイル探索・パス探索・不正入力パターン等の限定した分類。インシデントは調査単位であり、件数を足して攻撃回数と解釈しない。

## 記録経路と保護

Vercel Functionは公式SDKで現在の呼び出しの短期OIDCトークンを取得し、Supabaseの`security-collector`へバックグラウンド送信する。RS256署名、固定issuer/audience、所有チーム、プロジェクト名・ID、production環境、subject、有効期限を検証する。preview、別チーム・別プロジェクト、署名なし・期限切れのトークンを拒否する。VercelにSupabase管理用キーを配置していない。

Edge Function側は既存のサーバー専用権限を使って、限定した記録用RPCへ送る。受信後のSQLは許可した分類・対象のみ受け付ける。元のURIやクエリー、本文、Authorization、メール、パスワード、認証コードは記録しない。元IPは一時的にサーバーへ渡し、非公開の乱数キーを使うHMACと週単位の値で置き換える。IPv6は/64単位。同じ人・攻撃者の特定を保証しない。

記録用テーブルはすべてRLSを有効にし、anon・authenticated・service_roleから直接の読み書きを拒否する。取り込みRPCはservice_roleだけ、閲覧・対応RPCは確認済みのMFA、存続するAuthセッション、期限内の運営権限を毎回検証する。運営用トークンとメモの下書きはブラウザメモリーだけに置く。CSPとnoindexを適用する。

## 保持・流量・欠落

- 詳細は30日、10万件を目安に毎分整理する。上限を超えた詳細は古い順に1回最大1万件ずつ整理し、集計は残す。
- 時間別集計90日。インシデントは最後の更新から90日。対応操作の監査記録90日。これらはアプリ本体の写真・動画・投稿とは別であり、整理対象にユーザー投稿を含めない。
- 全体のイベント取り込みは最大6,000件/分、各実行環境は最大500件/分に制限する。原則として元のAPI応答を待たせず、送信は2.5〜3秒で打ち切る。
- イベントUUIDで保存済みの重複を排除する。送信失敗は次回の送信時に報告し、混雑で取り込みを拒否した際に前回の失敗報告を二重加算しない。
- ベストエフォートであり、実行環境が終了した場合の未報告分、到達前の遮断、プロバイダー障害、取り込み制限などの全欠落を正確に数えるものではない。「0件」は攻撃が存在しない保証ではない。

## 未連携の範囲

Vercel Firewall/DDoS対策がアプリ到達前に処理した通信、Supabase Auth・DB REST・Storageへ直接届く通信の拒否は、このアプリ観測だけでは網羅できない。監視範囲の画面に未連携と公式管理画面へのリンクを表示する。APIの認証エラーを、Authログイン試行の総数と表現しない。

VercelのDrainsはPro/Enterprise向け。プラットフォーム側ログを自動集約して網羅性を上げる場合は、プラン・利用量・費用を別途確認してから判断する。今回アップグレードは行っていない。既存プランのリソースは使用する。

参考: [Vercel OIDC](https://vercel.com/docs/oidc)、[OIDC claims](https://vercel.com/docs/oidc/reference)、[Drains](https://vercel.com/docs/drains/using-drains)、[Firewall observability](https://vercel.com/docs/vercel-firewall/firewall-observability)。

## 対応手順

1. 種類・件数・時刻・応答を確認し、単純な誤入力や正当な拒否と区別する。
2. 必要なら記録IDとリクエストIDでプロバイダーの公式ログと照合する。識別子だけから個人を断定しない。
3. インシデントを確認中にし、秘密情報や個人情報を含めず対応方針を記録する。
4. 防御・権限・アプリ不具合の修正が必要なら、具体的な対象と影響を確認して実施する。自動的なユーザー停止・IP遮断・外部への通報は行わない。
5. 確認を終えたら対応済みにする。必要な範囲のCSVを保管する場合も運営用の保管場所を使う。

## 配備と復旧

Vercelは既存の`codex/vercel-site`ブランチ、root `sites/mefrion-info`。`npm ci`、`npm run build`で読みやすいconsoleソースを既存ルーターへ埋め込む。依存はバージョン固定・lockfile管理、脆弱性監査済み。

Supabaseは202610260001〜202610260005のマイグレーションを開発・本番の双方に適用し、履歴に記録した。Edge Functionsは11本とも配備した。既存の写真取得・投稿・認証の許可判定を残し、監視を追加する。

サイト側に問題が出た場合は、Vercelで正常だった直前のデプロイを再昇格する。UIだけの復旧でもSupabase側の収集は独立して続く。Edgeの復旧は必要な関数を直前ソースで再配備する。監視DBを急いで削除したり、ユーザーデータや認証設定を巻き戻したりしない。

## 検証の範囲

Nodeの認証・ルーティング・分類・CSV等23テスト、Denoの送信失敗時の応答維持・秘匿・OIDC検証10テスト、DBの権限・MFA・セッション失効・重複・匿名化・インシデント・上限等43アサーションを確認する。DBテストの架空アカウントとログはすべてロールバックする。

本番では11関数の拒否応答、Vercelの短期OIDCからの実保存、少数の自サイト検証による探索10件と繰り返しインシデントの生成を確認した。その後Vercelが検証元にchallengeを返し、アプリ到達前の防御と観測範囲の限界も確認できた。追加の回避・大量試行・Firewallの無効化は行わない。

確認済みの検証イベントは削除せず`is_test`を付け、通常集計から除外した。ローカルの画面操作テストは架空データで明示し、本番には含めていない。所有者のMFAを使った本人による最終閲覧は未実施。検証証跡は`docs/evidence/SECURITY-MONITOR-*20261026*`。
