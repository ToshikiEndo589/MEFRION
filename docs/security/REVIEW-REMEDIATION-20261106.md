# 外部レビューの照合と修正

- 移行番号重複は実在。検索・コメントの050001/050002を維持し、運営ワークスペース/通知を050003/050004へ変更した。
- 本番supabase_migrations履歴には検索・コメントの2件だけ存在した。運営のテーブル・通知関数の修正版が存在することを確認し、SQL Editorで手動適用済みの050003/050004/060001を履歴へ採用した。既存データの作り直しはしていない。手動採用行のstatementsは空配列、実SQLはリポジトリに保持。
- 通知は本番でJWT検証off・内部トークン検証・cron有効・送信成功済み。再配備でも同じ状態になるようconfig.tomlと060002のcron登録を追加。
- social_pageの日時desc・ID ascに合わせ、同一日時の次ページ条件をID greater-thanへ変更。060003を本番へ適用。
- 本番のトランザクション内で合成投稿を作り、同時刻2件と古い1件を1件ずつ取得。欠落・重複なし、停止中の投稿は出ないことを確認。全fixtureはROLLBACKした。
- 移行番号チェックと重複検出の単体テスト2件、サイト回帰テスト25件成功。
- CIに空DBへの全移行適用と認証・権限・ページ送りSQLテストを追加。ローカルMacにはDockerがないため、空DB構築の実行はGitHub Actionsで確認する。
- 規約の重複文を生成処理で除去。
- 端末の犬猫判定をAPIクライアントが迂回できる点は既知。公開前の人間による確認を維持し、サーバー側自動分類を導入したとは主張しない。
