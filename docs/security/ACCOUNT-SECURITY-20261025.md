# 認証情報・個人情報の保護（2026-10-25）

対象: MEFRIONの本番／開発DBとAPI、配布用ソースとビルド済みiPhoneアプリ、Supabase管理アカウント。犬猫判定のサーバー移行は所有者の取り消し指示に従い実施していない。

## 実行・確認した対策

1. **他人の認証用メールアドレス等を返さない**
   - ロールバック専用の2アカウントに固有メール・電話・パスワード欄の試験文字列を設定。自分のプロフィール／家族メンバー／Pet一覧／公開プロフィール／社会関係の応答にこれらが含まれないことを検査した。
   - Authテーブルへの直接SELECTをanon／authenticatedで禁止。匿名のAuth管理API401、Auth schemaのREST読み出し406、本人プロフィール・運営API401を開発／本番で確認。
   - DBの関数定義に連絡先・認証情報の語が出る3つの管理用RPCは、anon／authenticatedから実行不可。通常の本人向けAuth応答が本人メールを返すこと、利用者が自ら投稿本文等へ書くメールアドレス、公開問い合わせ先はこの禁止とは区別する。
2. **アクセス権限**
   - 全内部テーブルのRLSと一般ロールへの直接DML拒否、security definerの固定search_pathを検査。
   - migration `202610250001_private_default_privileges.sql` を開発／本番へ適用。将来作成する内部テーブル／シーケンスと関数の暗黙アクセスを抑制。PostgreSQLの関数はグローバル既定PUBLIC EXECUTEを解除する必要があるため、新しい公開RPCは呼出者への明示GRANTを必須にした。既存の公開RPC・カタログの権限は変更しない。
   - 一般家族によるオーナープロフィール編集を拒否。既存アイコン32・招待17検査を各環境で再実行し成功。
3. **アプリへ管理キーを含めない**
   - Releaseの設定読み込みはHTTPSの許可されたSupabase URLと公開用`sb_publishable_`キーのみ。管理キーはアプリ設定として採用しない。
   - ソースとビルド済み `.app` の実行バイナリ・リソース18ファイルを検査し、検出0。公開キーは意図した配布設定として許可する。
   - 検査スクリプトを拡張：Supabase管理キー／PAT、GitHubキー、Brevo API／SMTPキー、AWSアクセスキー、秘密鍵、公開anon以外のJWTを検出。値を出さずファイル・行・種類だけを報告。既存CIが使う同スクリプトを更新した（今回の変更のGitHub pushは未実施）。
4. **ログと保存**
   - iOSのAuth通信はephemeral URLSession・キャッシュ無効。エラーを固定メッセージに変換し、応答本文やメール／パスワード／トークンをログへ出していない。
   - 配信Edge Functionsはエラーコードのみを返し、認証ヘッダー・本文・写真パス・例外本文をログに記録しない。運営コンソールのトークンはメモリ保持、共有用Pythonサーバーの既定アクセスログは無効。
   - 端末の継続ログインはパスワードでなくKeychainのトークンを使用。ロック解除時のみ・この端末限定の既存保護を確認。ログへ秘密値を追加しない形で検出スクリプトを強化した。
5. **二段階認証**
   - Supabase管理アカウントは当初未登録だった。所有者が画面上で認証アプリを登録し、完了後に「MEFRION」「Added on」の登録済み表示を確認。
   - SMSではなく認証アプリ方式。提供された実電話番号はコード・DB設定・公開ファイルに保存していない。TOTP設定キーや確認コードもファイルに保存していない。
   - アプリの運営APIは役割に加えAAL2と実在する検証済み認証要素を必要とする。パスワードのみ、および認証要素なしのAAL2 claimで拒否されることをSQLで確認。現在、アプリ内の人間用運営ロールは開発／本番とも0件で、新しい管理者権限を誰にも付与していない。

## 範囲の限界

Supabase管理アカウントの二段階認証を確認したものであり、GitHub・Google・Brevo・Appleアカウントの二段階認証設定を一括変更したわけではない。基盤提供者の内部ログや管理ダッシュボードの標準監査記録を無効化していない。フィッシング・端末感染等を含む漏えい可能性がゼロだと保証しない。端末側犬猫判定の直接API回避は、別報告のとおり所有者の選択で残っている。
