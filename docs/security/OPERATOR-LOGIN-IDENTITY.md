# 運営ログイン専用メールへの分離 — 2026-10-26

対象はMEFRIONの運営画面だけ。公開問い合わせ先・確認メール送信元・一般ユーザーのAuthメール・既存アプリの投稿やペット・Supabase/Vercel等の管理サービスのログインは変更しない。

所有者が指定した専用メールは、非公開の `mefrion_private.operator_login_allowlist` に設定した。公開サイト、公開設定、GitHubのコードやこの文書へ専用メールを埋め込まない。開発・本番に同じ方針を適用した。

メールでの本人確認後、運営画面は `mefrion_operator_login_eligible` で現在のアカウントだけの利用可否を確認する。不許可の場合は認証アプリ登録へ進めず、ブラウザ内のトークンを消去する。照会APIにメール引数はなく、他人のアドレスや許可リストを取得できない。

サーバー側でも、監視・通報対応・運営素材の管理・担当者の有効性・運営権限の付与を専用メールの許可と照合する。権限テーブルへの誤った直接追加もトリガーで拒否する。メールアドレスはAuthの確認済みの値を使い、自己申告のプロフィール名やメタデータでは認めない。アドレスを許可しただけで運営権限は付かない。MFA・有効なセッション・期限付きの役割は引き続き必須。

サービス専用の既存QA関数は、予約済みexample.invalidドメインかつ合成試験用と確認された本人データだけを許可し、無効化時にその試験許可を除く。人間のアカウントを許可する抜け道として使用しない。

本番には専用メールのMEFRIONアカウントがまだないため、本人が運営画面から新しい専用メールで登録・メール確認・認証アプリ設定を行う必要がある。その後、確認済みの新しい所有者IDに期限90日以内の運営権限をサービス手順で付与する。以前の一般ユーザーアカウントを改名・削除・統合していない。

検証: サイト24テスト、DBは運営メール方針14・監視43・アカウント安全性22の計79アサーションを開発と本番の双方で実施。合成データはロールバック。専用メールを公開ソースへ含めていないことも確認。
