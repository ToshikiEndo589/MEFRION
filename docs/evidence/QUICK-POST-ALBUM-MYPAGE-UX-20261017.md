# 新規投稿・アルバム・マイページの簡素化（2026-10-17）

## 変更

- 投稿タブの「公開投稿」は、Petの選択（1匹なら自動選択）、写真の選択または撮影、任意のひとこと、明示的な公開確認、画面下の「投稿する」へ整理した。写真を先にアルバムへ追加してから投稿画面で選び直す操作をなくした。公開確認は後日、写真とPetプロフィールをまとめた1つの大きなチェック行へ改修した。
- 投稿時の元写真は家族だけのアルバムに非公開保存し、写真提供者のSNS用途同意とPet公開の同意を確認してから公開要求を送る。元写真をそのまま公開フィードに配信しない。失敗したアップロードは端末の保護されたキューから再試行できる。
- アルバムの「写真を追加」は選択後に非公開保存する。通常導線の「写真を確認」画面をなくし、管理・公開許可・削除は各写真とアルバムの折りたたみメニューに置いた。保存が済んだ進捗カードは残さない。
- アルバム一覧とマイページはPetごとの短い行へ整理。犬猫を持たない登録者もマイページを使え、Pet追加は任意。登録画面のメール確認コードとパスワード再入力も維持。
- 「公開投稿／アルバムに残す」の左右切替、5タブの構成、家族写真の非公開・権限・削除連動は維持。

## 実際に確認したこと

- 当初はiPhone 17e / iOS 27 Simulatorで写真選択と2件の同意を合成Pet・同梱の検証用画像で操作し、開発Supabaseの受付後にテスト投稿と元写真を削除するUI試験1件が成功（`/tmp/mefrion-quick-post-e2e.xcresult`）。現行の1件の公開確認と投稿状態表示は [後続の検証](POST-STATUS-AND-OWN-LIST-20261017.md) に記録した。
- 同Simulatorで登録画面・投稿先左右切替のUI試験2件成功（`/tmp/mefrion-post-ux-tests2.xcresult`）。投稿導線のUI試験1件と単体42件成功（`/tmp/mefrion-post-ux-final-tests.xcresult`）。
- 開発Supabaseで合成画像による認証・元写真保存・明示同意・公開用画像生成・公開停止・削除の31項目を `scripts/verify_publication_e2e.py` で確認し、全件成功。テスト画像は削除し、試験Petの公開プロフィールを非公開へ戻した。結果は `docs/evidence/supabase-publication-e2e.json`。
- 画面画像で投稿ボタンが初回表示から隠れることを見つけて、下部固定へ修正した。投稿・アルバムの合成検証用ボタンは `--ui-test-isolated` のDebug UI試験時だけ表示される。
- 最終レイアウトで投稿導線・投稿先切替のUI試験2件成功（`/tmp/mefrion-post-ux-release-check.xcresult`）。投稿ボタンが画面内に固定された画像は [こちら](quick-post-sticky-20261017.png)。
