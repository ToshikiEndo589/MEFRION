# ホーム引っ張り更新で投稿が消える問題（2026-10-16）

## 原因と修正

- 本人報告どおり、公開投稿50件のある状態で上から引っ張って更新すると、「公開された投稿はまだありません」に変わることをSimulator UI試験で再現した。
- 開発Supabaseの匿名RPCは更新前後とも50件を返し、既知投稿50件の公開可否も有効だった。アプリのログでは、SwiftUIが更新中のネットワーク要求をキャンセルし、エラー処理が `clearPublicViews()` で全投稿を削除していた。
- 再取得の開始時に画面の投稿・写真を消さず、取得成功後にサーバーで有効と確認した投稿と写真だけを反映するよう変更。通信失敗やキャンセル時は既存の表示を保持し、エラーを上位処理へ返す。
- 引っ張り更新の要求をSwiftUIの `.refreshable` クロージャーから独立したタスクで実行し、画面再描画によるキャンセルで再取得が中断しないようにした。ホームタブ再タップと「フォロー中」の既存動作も維持する。

## 実際に実行した確認

- 修正前の実投稿50件UI試験で、引っ張り更新後に投稿0件・画像0件を確認。画面の記録はローカルの `.local/pull-refresh-diagnostic2-attachments/` に保存。
- 修正後の実投稿50件UI試験 `testLiveRecommendedPullToRefreshKeepsPostsVisible` 成功。先頭が別投稿に変わり、投稿と画像が残ることを確認。
- 回帰試験: 推薦順単体1件、ホームタブ再タップUI1件、実投稿50件の引っ張り更新・再タップ・画面復帰時スクロール維持UI3件。計5件成功、失敗0（`.local/feed-pull-refresh-regression.log`）。
- 署名付き実機Debugビルド成功（`.local/feed-pull-refresh-device-build.log`）。接続中のiPhone `00008140-001A74A22E90401C` へ上書きインストールし、`devicectl` から起動成功。

## 範囲

- 実機で人が画面を見て引っ張り更新する操作は今回未実施。Simulator上の実投稿50件試験と実機インストール・起動まで確認。
- この変更にSQLマイグレーションは不要。公開停止・ブロック・期限切れは、取得成功時のサーバー応答で除外する。通信失敗時は直前に確認済みの公開投稿を一時的に保持する。
