# ホームの読み込み改善（2026-10-13）

対象はiPhone Debug版のクラウド「おすすめ」および公開投稿一覧。承認済みの開発用20投稿で検証した。

## 原因と変更

- 従来は投稿RPCを12件ずつ取得し、そのページの公開画像を1枚ずつ全て受信してから投稿を画面へ渡していた。画像取得に時間がかかると一覧全体が空のままだった。
- 投稿RPCの結果を先に表示し、公開画像を6件ずつ並列で取得して各画像の到着ごとに表示する。失敗した画像には再読み込みを表示する。
- 1ページを30件へ増やし、末尾が表示されたら次ページを自動取得する。手動の「さらに読み込む」は削除した。投稿ビューをLazyVStackにした。
- 再取得時の画像は、サーバーがその投稿を再び閲覧可能と返した場合に限ってメモリから再利用する。アプリ非アクティブ化・認証無効化・公開取り下げの既存クリア経路は維持した。ディスクへの公開画像キャッシュは追加していない。
- 保存済みログインの復元で重複していた `/auth/v1/user` 照会を1回削除した。

## 実行した確認

- 開発Supabaseの匿名feed RPC: 対象20件、約0.53秒。`p_limit=30` で20件を一度に返し、次ページなし。
- 同じ公開画像へのHTTP実測: 12枚直列で8.63秒、20枚を6並列で2.25秒。端末の表示時間を直接測った値ではなく、通信条件で変動する。
- `p_limit=3` のページングを2ページ照会: 各3件、重複なし、既知ID3件のサーバー再検証成功。
- iOS Simulator Debugビルド成功。`testCloudHorizontalTabsAndPublicComposerDefault` UIテスト成功（既存のホーム切替・投稿タブ）。修正後の再ビルド成功。
- Simulatorに修正後のアプリをインストール・起動し、最初の投稿と公開画像が表示されたことを[画面](feed-performance-20261013.png)で確認。

実iPhoneは今回 `devicectl` で unavailable のため上書きインストールと実機速度の測定は未実施。公開投稿20件は以前の検証許諾期限が約48時間で、期限後の表示数は変わる。Instagram同等の起動時間を保証する測定は行っていない。
