# ホーム再タップ・公開フィードの追加高速化（2026-10-15）

## 実装

- ホームタブを選択中にもう一度押すと、公開フィードを先頭へスクロールして現在の「おすすめ／フォロー中」を再取得する。連打中の重複再取得を抑え、投稿表示中は小さな足あとで更新を示す。他タブからホームへ移るだけの場合は通常のタブ切替を維持する。
- 保存済みログインのアクセストークンが60秒以上有効なら、サーバーの本人確認を経てそのトークンを再利用する。毎回のrefresh-token要求を省く。期限切れ・サーバー拒否では従来の更新経路を使う。認証成立時にはPet一覧取得と並行してフィードを取得し、画面側の初回取得と重複しないよう同じIDの開始を1回にまとめた。
- 公開写真の最初の6件は60msの段階待ちを外して直ちに並列取得する。各JPEGの復号は明示的にUIスレッド外へ出す。表示中の写真と次ページ先頭の写真の優先取得、最大24枚のメモリ保持、公開状態の再検証とno-storeゲートウェイは維持した。
- 復号済み写真24枚に加え、圧縮済みJPEGをプロセス内メモリだけに最大96件・合計24MBまで保持する。前の投稿へ戻る時は通信せず再復号する。サーバーから再検証された投稿の画像だけ保持し、公開停止・ログアウト・同意撤回では消去する。端末ディスクへの永続化はしない。
- 初回／更新ページでは再利用候補の検証IDを先頭30件に限定した。新しいページに含まれない古い写真は再利用しない。ページ追加では保持中の全投稿IDを検証し、公開終了した投稿を残さない。
- 30件ページの末尾6投稿が画面に近づいた時点で次ページを先読みする。末尾の読み込み表示に到達してから要求する旧動作より、通常スクロールで待ちが出にくい構成とした。
- 投稿数が増えた時のkeyset順序と逆向きブロック照合に対し、DB索引追加のマイグレーションを用意した。今回は開発Supabaseへ未適用で、現行サーバーの速度改善には算入しない。
- 隔離UIテスト専用に20件の犬投稿を作る起動引数を追加した。通常起動・Releaseでは有効にならない。
- Debugログにフィードのメタデータ取得時間、画像の通信時間・復号込み総時間を個別IDなしで記録する。実投稿が再開した時の遅延原因の切り分けに使う。

## 実行した確認

- Simulatorのホーム再タップUI試験: 20件の隔離投稿をスクロールし、再タップ後に先頭投稿へ戻ることと投稿データの再取得を確認。1件Passed。
- 最終のiOS試験: 単体40件、ホーム再タップUI1件、5タブ／検索UI1件の計42件Passed、失敗・skip0。結果 `/tmp/mefrion-home-refresh-final.xcresult`。この後に追加した末尾6件先読みの最終コードはSimulator Debugビルド成功。先読みの実投稿UI試験は未実施。
- 末尾先読み追加後、ホーム再タップUI試験を別途再実行して1件Passed（`/tmp/mefrion-home-reselect-final.xcresult`）。その後に加えたDebug計測コードもSimulator Debugビルド成功。
- 圧縮メモリキャッシュ追加後、隔離20投稿のホーム再タップUI試験を再実行し1件Passed（`/tmp/mefrion-home-cache-final.xcresult`）。最初の2枚だけを復号済みにして、後続投稿のJPEGをメモリから復号して表示できることも確認した。実ネットワークの短縮時間は測定していない。
- Python全96件Passed、`scripts/check_repository.py`成功。最初のPython実行はXcode付属PythonにPillowがなくimportエラー4件で失敗、同梱依存環境のPythonで再実行して全件成功。
- 圧縮キャッシュの上限処理を含む最終コードでSimulator Debugビルド、署名付きiPhone Debugビルド、`codesign --verify --deep --strict`が成功。物理iPhone (59)はCoreDeviceで`unavailable`のため今回の上書きインストール・実機操作は未実施。
- 開発Supabaseへの匿名フィードRPCをMacから同条件で7回測定。返却投稿は全回0件、通信時間は460.0、126.2、116.2、126.5、148.6、137.6、127.1ms（中央値127.1ms）。最初の通信が遅く、実投稿画像の表示時間や変更前後の同条件比較には使えない。

## 未検証と制約

検証用の公開投稿は権利期限後で0件。実際の犬猫画像があるフィード、セルラー回線、長時間スクロール、休止復帰、同時利用者負荷での表示時間を測れていない。公開停止・ブロックを反映するため、再検証中の公開画像を隠す挙動は維持している。電波不良やサーバー応答遅延時の待ち時間をゼロにする変更ではなく、Instagram同等の体感速度は未実証。
