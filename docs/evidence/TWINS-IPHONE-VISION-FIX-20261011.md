# 実iPhoneのEspresso読み込みエラー修正

## 報告と原因の確認

利用者の実機スクリーンショットで `Loading espresso Network [espresso error: -2]` と検索失敗を確認。Visionの「Network」は画像認識モデルの処理であり、ここで入力写真を外部送信する構成にはしていない。

認識・特徴抽出の両リクエストに `usesCPUOnly=true` を一律設定していた。接続中のiPhone 16で、Debug限定のCPU固定プローブが認識処理失敗を返し、同じ同梱写真をVisionの既定処理先で実行すると768要素の特徴抽出が成功した。CPU固定による実機失敗をA/Bで確認した。初回のSimulator成功を実機認識の成功と扱えなかった点を訂正する。

Appleの[usesCPUOnlyの説明](https://developer.apple.com/documentation/vision/vnrequest/usescpuonly)では既定値falseでGPUによる高速処理が可能。実機では指定を除きVisionに処理先を選ばせる。Macの索引生成とSimulatorのみ既存のCPU設定を維持する。別revisionの特徴へ切り替えたり、不正な画像を認識済みとして通過させたりしていない。

## 変更

- 実iOSはVisionの既定処理先を使用。
- Vision実行エラーは写真不良/候補不足と区別し、日本語の再試行案内を表示。診断ログは処理段階・NSErrorドメイン/コードのみ。入力画像・特徴量・個人情報は記録しない。
- 実機では同じ犬写真の索引との差が0.25292587となり、距離0.08による除外だけでは自己写真が混入した。9x9グレースケールの水平/垂直144差分と平均明度による画像指紋を追加し、同じ/ほぼ同じ参考写真を保守的に除外。入力の指紋は検索中のメモリ内のみ。指紋一致は個体一致/別写真の同一個体を意味しない。
- Debug限定の実機プローブを追加。明示起動引数でのみ動作し、同梱参考写真だけを読み、端末のprivate-stateやクラウド認証を読み込まず、写真/履歴/投稿を変更しない。Releaseにはプローブ画面を含めない。

## 実行結果

実機の通常署名Debugビルド成功、既存Bundle Identifierを保持して更新インストール成功。実機プローブで犬・猫とも特徴768、候補3件、自己写真除外true、最後の `COMPLETE PASS` を確認。犬/猫の距離と件数のみをログに記録。最後に引数なしで通常アプリを起動した。

プローブは画面のライフサイクル変化で一部タスクがキャンセルされ、初期の診断では自己写真混入が失敗扱いとなった。ログを隠さず保存し、最終の両種の完走PASSと区別する。コンソールを待ち続けるCLIには25〜45秒の上限を設けたため、CLIタイムアウトを検索失敗とは数えない。最終の指紋差分12のビルドでも実機の両種候補3件・自己写真除外・完走PASSを確認し、`twins-iphone-shipping-device-probe.log` に保存した。

実機XCTestの最初の試行はテストターゲットの開発Team未設定でビルド前に失敗。新しいテスト証明書/プロビジョニングを作る代わりに、既存の署名済みアプリ内の明示プローブを使って実機処理を確認した。実機XCTest成功とは主張しない。

Simulatorでそっくり単体6件＋UI1件を実行し、最終再実行は全7件成功。画像指紋の縮小耐性/異なる形状、犬猫索引/自己写真除外、向き/解像度、白紙/索引欠落、通信失敗、本人履歴の保護/期限/削除、画面での検索/写真変更の再確認/入力破棄を対象とした。結果は `twins-iphone-final-simulator.log` と `twins-iphone-fix-summary.json` に保存した。前回49件の全回帰を今回再実行したとは扱わない。

初期の指紋差分2以下では縮小画像のテストが1件失敗（144差分中9、平均明度差1.358）。同一写真のリサンプリング差を許容する暫定値12へ変更して再実行。初回失敗と診断ログも保存する。全写真の誤除外率を校正済みとはしない。

## 残る確認

利用者が送った実写真そのものはスクリーンショットの一部しかないため、その元写真での再検索は未確認。実機カメラ/写真ライブラリの手操作、似ている品質の合格判定、全クラウド経路は引き続き別の未検証項目。今回の修正は認識モデル読み込みと自己写真混入への対応であり、そっくり品質の本番合格ではない。
