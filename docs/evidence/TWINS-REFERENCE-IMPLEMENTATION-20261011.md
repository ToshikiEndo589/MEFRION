# 2026-10-11 そっくり検索の実装・検証記録

## 実装したこと

現行の犬猫候補5,221枚をApple Visionで処理し、犬2,578・猫1,834の計4,412枚を検索索引としてiOSアプリに同梱した。認識/特徴を確認できなかった809枚は除外した。元の素材を削除せず、APIキーの再利用や新しい外部サービス契約は行っていない。

そっくりタブの通常経路を端末内の参考写真検索へ変更。選択/カメラ、向き補正、切り抜き、犬猫選択、写真ごとの検索確認、主候補1＋補助最大2、候補不足/写真不良/障害、キャンセル、評価、本人ログイン後の任意履歴保存、履歴削除、別途確認後の画像共有を実装した。写真の差し替え時には検索確認をOFFへ戻す。

入力写真はネット送信・索引登録・履歴保存をしない。画面終了/非アクティブ/破棄/10分で入力と結果を消す。履歴は候補ID・種類・日時・本人IDのみ、端末の既存保護ファイルへ保存し24時間・最大20件。退会時の端末データ消去にも含める。共有カードには入力写真が含まれるため独立した確認を必須にした。

Pexels素材を架空のPetプロフィール/飼い主/犬種・個体ラベルにしない。撮影者と出典を表示する。公開Petの検索は別入口で既存サーバーの掲載同意・公開状態・ブロック・削除連動・上限の経路を保持し、画像比較部分をVisionへ変更した。参考写真の端末内検索は無料・オフラインであり、既存公開Pet検索のゲスト/会員上限とは別の経路。

実装・再生成・制約は [TWINS-REFERENCE-INDEX.md](../operations/TWINS-REFERENCE-INDEX.md)。大きな生成素材はGit対象外。別環境のビルドには元素材と索引の再生成が必要。

## 実際に実行した検証

- Python全85件成功。`twins-reference-python.log`。
- Simulator全オフライン実行で単体34＋UI13＝47件成功。クラウド依存UI17対象は除外。`twins-reference-ios-full.log`。
- カメラ画像の向き/2048px上限と通信障害の伝播の2件を追加し、そっくり単体5件＋UI1件を再実行、成功。`twins-reference-ios-targeted.log`。今回実行した異なるiOSテストは合計49件。重複した再実行を別の件数には数えない。
- 犬/猫の実写真による索引読み込み・自己写真除外・種別分離・最大3件、白紙/索引欠落、任意履歴/TTL/全消去を単体テスト。UIで実写真検索と入力/結果の破棄を確認し、画像を目視確認した。最終の写真差し替え確認リセットも同じUIテストに追加し、単体5＋UI1件を再実行して成功。`twins-reference-ios-confirmation.log`。
- 4,412画像の存在、索引と画像数の一致、犬猫限定・demoOnly・HTTPS出典、特徴バイナリ13,553,664 bytesを検証。`twins-reference-summary.json`。
- 既存の署名設定とBundle Identifierを保持して実機Debugビルド成功。接続したiPhone (59)へアンインストールせず更新し、`devicectl`でインストール成功とプロセス起動成功を確認。既存の家族写真/投稿/サーバーデータの消去は行っていない。
- 最終確認時に並行した実機ビルドとテストが同じビルドDBで競合して一度失敗。ビルド終了後に逐次再実行し成功した。`twins-reference-build-conflict.log`。初回UI試験の待機対象も実際の表示ラベルに合わせて修正した。
