# 運営投稿1,000件と毎日100件の入れ替え

2026-10-24。対象はMEFRIONの本番と、現在の実機が接続する開発環境。

- 目標は閲覧可能な運営投稿1,000件。一般ユーザーの投稿はこの数に含めない。
- 毎日00:05 JST以降、当日1回の入れ替えを開始。毎分Cronが1回20件まで処理し、通常は数分かけて100件を差し替える。Macは不要。
- 削除対象は運営投稿で、いいね0・有効なコメント0の両方を満たすもの。古い順に選び、一般ユーザーの投稿は対象外。保存だけの投稿は指定の削除条件に該当する。
- 新しい写真の保存と公開に成功したトランザクションでのみ古い投稿を停止する。失敗時は古い投稿を維持し再試行する。
- いいね/コメントの追加と同じ投稿行をロックし、削除直前にもう一度判定する。反応が付いた候補は保護する。対象不足時は条件を満たす分だけ入れ替える。
- 同じ日に複数回Cronが動いても追加枠を増やさない。写真/処理IDは永続化し、通信障害でも同一投稿を重複作成しない。3分リース・最大12回の再試行、枯渇した処理はfailedで保持する。
- 新しい運営投稿は犬猫ごとの名前を持つ。犬種/猫種は既存の元データに明確な記載がある場合のみ設定し、それ以外は空欄。架空のいいね・コメントは作らない。

## 写真と権限

既存の稼働中Pexels犬猫データと、非公開reference-thumbnails内のJPEGを使用する。新しいAPIキーやPexels API呼び出しは不要。既存カタログのプレビュー写真（最長辺320px）を流用しており、新たに高解像度の原画像を取得したわけではない。

元ページ・撮影者・用途と所有者による利用承認をDBのカタログ/写真権利情報に保持。自動処理用の技術アカウントはログインを禁止し、パスワードや利用者向けアカウントを発行しない。管理対象の由来はcontent_origin=managed_seedとしてDBに残る。

カタログの許諾確認期限は登録から365日。期限切れ・無効化された候補は新規公開しない。期限後の継続には利用条件の再確認が必要。今後参考データ全体の削除/利用停止を行う場合は、既にコピーした運営投稿の権利も併せて撤回する。

## 構成

- `supabase/migrations/202610240001_stock_daily_rotation.sql`: 専用ポリシー/候補/実行/タスク、権限、公開完了・安全な入れ替え。
- `202610240002`・`202610240003`: 検索インデックスとリース枯渇の可視化。
- `202610240005`: 公開投稿のPet/写真参照インデックスと、公開のたびに全1,000件を判定し直さない予約枠チェック。
- `202610240004`: 新しい候補と1,000投稿のデータを暗号化バックアップへ含めるため、平文上限を8から32MiBへ変更。暗号方式・7日保持・保存先・プランは変更しない。
- `supabase/functions/stock-worker/`: 内部トークン認証、予約済みパスだけへのJPEG保存と公開確認。
- `scripts/configure_stock_rotation.py`: 所有者承認済みの既存候補を登録。書き込みには明示的な`--apply`が必要。途中までの登録では新しく有効化しない。
- Cron名 `mefrion-stock-cycle`。Supabaseの既存内部トークン/Vaultを使用する。管理API用の短期トークンやMacは常時処理に不要。

## 運用と安全な停止

運営者のDB管理接続で、次の読み取りにより状態を確認する。一般アプリにはこれらのテーブル/RPCを公開しない。

```sql
select target,daily,enabled,last_day from mefrion_private.stock_policy;
select day,kind,goal,state,completed_at from mefrion_private.stock_runs order by created_at desc limit 10;
select state,error_code,count(*) from mefrion_private.stock_tasks group by state,error_code;
select jobname,schedule,active from cron.job where jobname='mefrion-stock-cycle';
```

停止する場合は`stock_policy.enabled=false`にする。写真を保存中の処理も完了時に再確認し、公開せず削除キューへ回す。failedを確認せず一括リセットしない。

Freeの保護余裕としてDB350MiBまたはStorage800MiBを超えた場合、新規計画を停止する。有料化は行わない。バックアップの平文32MiB上限も有限で、将来の履歴増加時には監視と対応が必要。

古い投稿の公開画像と、他の公開投稿から使用されない運営原本は既存のサーバー削除キューで消去する。投稿の停止記録・処理履歴は監査用に残す。暗号化バックアップには保持期間中のコピーが残る。

## 検証

`supabase/tests/stock_rotation.sql` はトランザクション内の専用QAデータのみで実行し、必ずROLLBACKする。DB内に試験用Storageメタデータを作るため、実画像の転送確認とは別の試験。24項目を本番・開発で通過し、元の利用者データはコミット変更していない。

Denoのパス安全性4項目、稼働エンドポイントの無認証拒否、通常の公開画像取得も確認。初回投入の一部に一時的な完了エラーがあったが、キューの再試行で回復することを確認した。最終件数と未解消エラーは`docs/evidence/STOCK-ROTATION-20261024.json`を参照。
