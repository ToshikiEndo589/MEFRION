# MEFRION メール登録の配信設定

2026年11月1日更新。本番・開発の Supabase Auth は、既存 Brevo SMTP を通じて `MEFRION <mefrion@mefrion.com>` から送信する。Google Workspace の受信設定は維持する。

- Brevo で `mefrion.com` の所有確認 TXT、DKIM CNAME 2件、DMARC を検証し、認証完了を確認した。送信元も Verified。
- Google の MX `smtp.google.com`、SPF `include:_spf.google.com`、Google DKIM は維持。Brevo 用 DKIM のセレクターとは別。ルート SPF を追加して二重化しない。
- DMARC は `v=DMARC1; p=none; rua=mailto:mefrion@mefrion.com`。集計レポートは所有者のメールで受け取る。メール拒否ポリシーは導入していない。
- Supabase の両環境で送信元を保存し、画面再読み込みで確認済み。ホスト `smtp-relay.brevo.com`、ポート `587`、既存 SMTP ログイン・キーは維持。秘密値はリポジトリ・チャット・ログへ残さない。
- 本番の登録確認・復旧・運営ログインメール、および開発の登録確認・復旧メールの問い合わせ先を更新。確認コードの `{{ .Token }}` と既存件名は維持した。開発の既定 Magic Link 本文には旧問い合わせ先がないため変更しない。
- 公開サイトの問い合わせ先も新アドレスに更新済み。iOS の問い合わせ先は更新ビルド済みで、実機インストールは次回接続時。

新アドレスで本人がメール確認と認証アプリ登録を完了した。確認済みの許可対象アカウントだけに、既存のサービス専用関数で90日間の moderator 権限を設定した。期限は2027年1月30日（JST）。実際の本人セッションで通報一覧取得とセキュリティ集計の表示を確認した。認証コード・設定キーは取得していない。

新アドレスへの確認メールを本人が受信し、登録を完了したことを確認した。受信ヘッダーやメールボックス内の振り分けは未検査。コードは読み取らない。ドメイン認証だけで受信側の振り分けや到達を保証しない。Brevo の有料プラン・新しい課金は追加していない。

Squarespace のドメイン登録連絡先メールも、所有者の依頼により2026年11月1日に認証完了。公式メールの確認リンクを開いた後、管理画面を再読み込みし、ドメインが「有効」で認証要求が消えていることを確認した。これは SMTP の送信ドメイン認証とは別。

## 2026年11月1日の登録メール再点検

所有者が指定した宛先は本番・開発とも既にメール認証済みだった。Supabase は登録済みの宛先への再登録に、アカウント有無を隠す成功応答を返し、確認メールを送らない場合がある。成功応答を配信保証として扱わない。

両環境のメール認証有効・新規登録有効・メール確認必須を公開 settings API で確認した。所有者メールの検証用エイリアスに対し、各環境で未確認のテスト登録を1件ずつ実施。Brevo のログで両方とも20:30 JSTに Delivered を確認。所有者指定のiCloud宛ての復旧メールも20:31 JSTに Delivered。コード・パスワード・受信メール本文は読み取っていない。受信サーバーの受領と受信トレイへの表示は区別する。

iOS のコード待ち画面に、登録済みなら確認メールが届かない旨とログイン・復旧への直接導線を追加。再送の案内も、登録状態に関係なく配信済みと断定しない。宛先の登録状態を照会する公開APIは追加せず、全ての新規登録に同じ案内を表示する。

画面の自動試験は、Simulator のパスワード入力補助と自動入力の競合で1文字しか入力されず、コード画面までの試験を完了できなかった。これは実送信のHTTP試験とは別で、全画面テスト成功とは扱わない。実機ビルドは成功し、導線修正のインストール・実機画面確認は端末の再接続時に行う。
