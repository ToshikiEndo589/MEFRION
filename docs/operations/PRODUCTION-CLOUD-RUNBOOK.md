# クラウド処理の運用

2026-10-23。対象は本番 `pbnimpqrthvznbwewtcf` と開発 `pmrvzpuznwzuejbuhaqm`。
Macはビルド・配備時だけ使用する。アプリの日常処理の常時稼働には不要。

## 動作

1. SQLが利用者・提供権限・現在の公開設定を検証して依頼を記録。
2. コミット後のトリガーと毎分Cronが、永続キューをEdge Functionsへ配信。
3. 画像1枚、動画1本、ポスター1枚を別実行で処理し、メモリ使用を制限。
4. 完了時にも提供権限を確認して公開。途中停止・通信障害は再試行する。
5. 削除はStorage上の消去を確認して完了とする。退会はAuthの削除状態も再確認。

リースは3分、最大12回再試行。待ち時間は指数的に増加し最大1時間。
失敗した依頼を消さず保持する。未処理件数・最古時刻・最終成功・失敗回数は
公開Siteの `/console/` で担当権限とMFAのある運営者だけが参照できる。
過去の失敗回数は成功後も残るので、現在の未解消失敗と区別する。

## 認証と秘密情報

ブラウザへ配るのはpublishable keyのみ。service-role keyはEdgeランタイム内部。
内部キュー用トークン・バックアップ暗号鍵はVault、管理用短期トークンは
Git無視対象の `.local` に0600で保管。トークンの期限切れは定期処理を止めない。
移行トークンは2プロジェクト限定、7日間。日常稼働には不要。

本番のSQLは `supabase/migrations/`、配備は `scripts/deploy_production_functions.py`。
開発移行は `scripts/migrate_development_cloud.py`。失敗時はDB記録を先に確認し、
既存移行を無条件に再適用しない。顧客写真・パスワード・メールコードをログへ出さない。

## バックアップの範囲

毎日03:30 JST、DB内でAES256暗号化・圧縮したスナップショットを
非公開の `system-backups` へ保存し、読戻しとハッシュを確認。保存期間7日。
対象はアプリの行データとAuthのユーザー・ID・MFA情報。再生成できる参考写真
ベクトル、処理キュー履歴、Storageメディア本体は対象外。
非圧縮JSON8MiBを上限とし、超過時は失敗を記録する。

これは同一プロジェクト内の論理スナップショットであり、完全なDBバックアップ、
PITR、写真・動画の復元、プロジェクト喪失に備えた独立バックアップではない。
追加で写真・動画を含む独立バックアップをSitesの非公開R2へ配備し、復元試験を実施した。
[OFFSITE-BACKUP-RUNBOOK.md](OFFSITE-BACKUP-RUNBOOK.md) を参照。

## 制約

Freeプランの容量・CPU・実行回数制限を受ける。今回有料化はしていない。
サーバー動画処理はiPhoneが書き出す5分以内・50MiB以内のMP4を対象にし、
サーバーで任意コーデックへの再圧縮はしない。入力不正は公開せず失敗記録を残す。
