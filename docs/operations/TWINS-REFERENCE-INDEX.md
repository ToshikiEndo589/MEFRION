# 犬猫写真を使ったそっくり検索（旧端末内fixture）

2026-10-11更新：通常の参考写真検索はサーバー方式へ移行。現行仕様は[TWINS-SERVER-SEARCH.md](TWINS-SERVER-SEARCH.md)。以下は隔離試験用に保持した旧4,412枚の説明。

## 構成

ホームの「そっくり」タブから `ReferenceTwinsView` を開く。参考写真の検索はネットワーク接続不要。写真選択/撮影、切り抜き、犬猫選択、確認、検索、主1・補助最大2、候補不足/写真不良/障害の区別、評価、任意の履歴保存、明示確認後の画像共有を備える。

ストック写真を実ユーザーや実在Petのプロフィールに見せかけない。参考写真・Pexelsの撮影者と出典を表示する。「公開Petから探す」は既存の `CloudTwinsView` へ進み、公開状態・掲載同意・ブロック・撤回・退会・ゲスト/会員の利用上限を検証する既存サーバー経路を使う。参考写真の端末内比較には外部原価やサーバー利用上限を適用しない。

## 画像比較

Apple Visionの `VNRecognizeAnimalsRequest` revision 2で犬猫の領域を確認し、`VNGenerateImageFeaturePrintRequest` revision 2の768個のFloat特徴量で比較する。自前の学習・外部AIへの写真送信は行わない。

入力は同じ種類の対象が複数いる場合に切り抜きを案内する。候補索引は犬猫の領域を切り抜いて特徴量を作る。参照写真に複数の同種動物がいる場合の候補特徴は最も確信度の高い領域で作成するため、個体ラベルとして扱わない。

実機はVisionの既定処理先を使い、CPU固定はMac/Simulatorだけに適用する。実機のCPU固定でモデル読み込み失敗を再現したため変更。同一写真でも縮小/処理環境で特徴距離が変わるため、候補採用前に9x9明度の144差分指紋（差分12以下・平均明度差4以下）でも入力/採用済み参考写真との重複を除く。これは写真の近重複判定であり、ペットの個体識別ではない。縮小試験で9差分が発生したため初期の2から補正した。値は暫定で、全写真について誤除外ゼロとはしない。

認識ラベルの確信度0.35以上、特徴量距離の最大1.1、重複距離0.08は**暫定の実装値**。類似度のパーセントには換算しない。距離が小さい候補のうち、同一/ほぼ同じ写真を除いて最大3件。基準外なら不足として返し、水増ししない。同じ個体の別写真は、個体の正解ラベルがないため完全に除外できるとはしない。

参考索引は元の犬猫候補5,221枚から4,412枚を採用（犬2,578・猫1,834）。認識/特徴が確認できなかった809枚は不採用。画像は320pxまでの既存サムネイル、特徴量バイナリは13,553,664 bytes、全リソース約80MiB。検索入力は長辺2,048px以内に正規化し、カメラの回転・鏡像を反映する。

## プライバシーと履歴

入力写真・特徴量はメモリ内のみ。候補DBに自動追加しない。10分・画面終了・アプリ非アクティブ・破棄操作で入力への参照と結果を消し、検索タスクをキャンセルする。画像・特徴量を履歴やログへ保存しない。処理中のOS内部メモリが物理的に即座にゼロ化されることまでは主張しない。

履歴保存は本人ログインとボタン操作が必要。既存の保護された、バックアップ除外のprivate-state.jsonに候補ID・日時・種類・本人IDだけを保存。本人IDで表示を分離し24時間で非表示/復元対象外、最大20件。削除/端末データ消去/全Twins履歴消去と連動。ログアウト/切替が画面から検出された際にも本人の参考履歴を削除する。

共有は画像のプレビュー後に外部共有への確認をONにしてからOS共有シートへ進む。入力写真がカードに含まれるため、検索の確認とは別に確認する。永続する共有URLの発行ではない。既存公開Petの共有URLはサーバー側の掲載同意/削除連動経路を使う。

## 再生成・撤回・差し替え

APIキーは不要。元のローカル素材一覧と権利記録を用意する。候補追加/撤回時は素材の主一覧から該当IDを追加/除外して**別の空フォルダ**へ生成し、検証成功後にリソースを差し替えて再ビルドする。元の素材・家族写真を削除しない。

```sh
xcrun swiftc -O ios/MEFRION/PetVisualFeature.swift scripts/build_twins_reference_index.swift -o .local/build-twins-index
.local/build-twins-index .local/pexels-pets .local/TwinsReferenceData-next
```

`catalog.json`のID順と`vectors.bin`の行順を一緒に扱う。片方だけ変更しない。アプリ側はバージョン、revision、要素数、長さ、非有限値、重複ID、種別、demoOnly、ファイル名を検証し、破損を候補不足と混同しない。変更後は `ReferenceTwinsTests` と新規画面テストを実行する。

生成された `ios/MEFRION/TwinsReferenceData/` は大きな写真を含むためGitには含めない。配布・複製にはこの生成手順と元の素材ライブラリが必要。既存の署名済みXcodeプロジェクトをジェネレーターで上書きしない。

同梱素材の撤回は更新ビルドと端末更新が必要で、旧インストールのオフライン写真が遠隔で即消去される構成ではない。この参考データを実ユーザーの公開Petや、即時撤回が必要な本番Pet候補には使わない。

## 品質の未完了

写真数の充足、特徴抽出、自己写真除外と画面操作の成功を「似ている精度が合格」と読み替えない。独立した実写真、犬猫/毛色/顔立ちの偏り、別写真での順位安定性、人物・商標等の内容、主観的な「似ている」の確認と基準の承認が必要。Appleの汎用画像特徴は血縁・個体識別・ペット専用モデルではない。

一次資料：[Appleの画像特徴量リクエスト](https://developer.apple.com/documentation/vision/vngenerateimagefeatureprintrequest)、[特徴量の距離比較](https://developer.apple.com/documentation/vision/vnfeatureprintobservation)。このMacのXcode 27 SDKヘッダーとSimulatorでrevision 2を確認した。
