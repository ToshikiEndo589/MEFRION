## 初回移行時の実装範囲（以下は旧v1の記録）

iPhoneの通常「そっくり」はReferenceTwinsServiceから既存Supabase Freeのpgvector HNSW検索に接続する。写真はVision revision 2で犬猫領域を切り抜き、768個のFloat・144bit近重複指紋・平均明度・種類に変換する。利用者が検索ボタンを押すと、この数値だけをHTTPS RPCへ送る。別の同意スイッチは設けないため、送信内容を検索画面で事前に説明する。サーバーは種類別の候補から近い100件を取り、基準外・近重複を除いた最大3件を返す。写真のJPEGは送らず、家族原本にもアクセスしない。

距離・動物認識基準は従来と同じ暫定値。汎用Vision特徴であり犬猫の顔専用モデルではない。サーバー化・候補増加の実装完了と、主観的な類似品質の合格は別である。「公開Petから探す」は従来の同意・権限・ブロックを伴う別経路で、まだ端末で公開候補を比較する。

## 保存と配信

参考写真の特徴と出典はservice_roleだけがアクセスできるRLSテーブルに格納。参照画像はprivateのreference-thumbnailsバケット。public-image Functionが掲載状態をダウンロード前後に確認し、no-storeで配信する。既存の家族原本/private-image/public-derivedの権限は広げない。

検索入力の数値は検索関数の引数として処理し、テーブルやアプリログには保存しない。候補ID・利用者/端末識別子を含む再試行記録は10分で利用終了、期限切れ行は次の検索で削除。日次カウンターは検索時に当日を含む3日を残して整理する。物理消去の定時ジョブや通信基盤のログTTLを配備済みとはしない。

参考写真専用の開発制限はゲスト10/会員50回/JST日。再試行UUIDを10分以内に再送しても追加消費しない。端末UUIDによるゲスト制限は強固な不正利用防止ではない。本番のインターネット公開前にはgateway/IP側の制限・監視が必要。実Pet検索のゲスト初回1/会員5回制限は変更しない。

iPhone実機ビルドはTwinsReferenceDataを除外し、候補の全ベクトル・全画像を同梱しない。Simulatorの隔離試験だけは既存4,412枚の索引をfixtureとして使う。ネットワーク障害時に端末内検索へ黙って切り替えない。Release向け接続キー/正式提供設定は既存の公開準備手順で別途整える。
