# 本番バックエンドの現在地

2026-10-23更新。東京のSupabase Free `MEFRION-production`
（`pbnimpqrthvznbwewtcf`）に68件のSQL移行、9つのEdge Functions、
4つのCronを配備した。開発のユーザー・私的写真・投稿は本番へコピーしていない。

## サーバーで稼働する処理

- 写真の縮小・向き補正・メタデータ除去、公開画像の作成。
- 動画の検証・メタデータ除去・再生開始用moov最適化、ポスター画像作成。
- 公開投稿、そっくり参加・共有の派生処理、承認済み予約投稿の配信。
- 公開停止、画像削除、退会に伴うファイル削除とAuthの退会完了。
- 毎分のキュー処理、毎時の期限切れデータ整理、毎日の暗号化DBスナップショット。

各処理はDBの永続キューに記録し、リースと再試行で途中停止から復帰する。
利用者の認証・同意・提供権限をSQL側で再検証する。内部処理用トークンと
service-role keyはアプリ・公開Web・Gitへ含めない。

本番のそっくり検索用素材は14,915件、DINO特徴量は14,907件。
これらのサムネイル約209MBもSupabase Storageに移した。
公開検索RPCで候補を返せることを確認済み。

共有ページとMFA必須の運営コンソールは既存の公開Sitesへ配備した。
https://mefrion-support.toshiki1108.chatgpt.site/console/
公開ページは共有専用のSQL投影だけを取得し、アルバム原本にはアクセスしない。
運営コンソールには公開キーだけを含め、ログイン・担当権限・MFAをSQLで要求する。

本番のBrevo SMTP、確認・復旧の日本語コードメール、公開Site URL、
`mefrion://auth-callback`を設定した。メール確認を必須とし、新規登録を有効化。
本番のパスワード最小長をアプリと同じ12文字へ揃えた。
実送信試験で検出した500「Error sending confirmation email」は修正済み。
管理APIのハッシュ値をSMTPパスワードとして扱った誤りを、本番専用の正しいBrevoキーで修正した。
所有者のテスト用メール別名で、確認・復旧メールの受信トレイへの到着、コード確認、
登録後ログイン、復旧後の新パスワードでのログインと旧パスワード拒否を確認した。
開発環境の既存SMTPキーは変更していない。試験アカウントは通常の退会処理で削除完了。
本番SMTPキーは `MEFRION production Auth`、期限2027-10-23。90日間未使用でも失効するため運営で管理する。

## 検証

- 4000pxのJPEG2枚の公開、EXIF除去と縮小。
- 約48MBのMP4とポスターを別処理で公開、サーバー出力をAVFoundationで再生可能と確認。
- 認証なし・不正内部トークンを拒否。
- 共有ページの表示、公開停止後のリンク無効化。
- 合成データだけの退会を要求し、Auth退会・原本と公開ファイルの消去完了。
- 暗号化スナップショットを保存・ハッシュ確認し、15個の非空テーブルを
  一時テーブルへ復元してロールバック。既存顧客データは変更していない。
- Python16件、Denoメディア4件、Release Simulatorビルド成功。

結果は `docs/evidence/PRODUCTION-CLOUD-WORKERS-20261023.json` などに記録。

## 実機が使う開発環境

`MEFRION-development`にも同じ8つのEdge Functionsと8件のクラウド移行、
3つのCronを配備した。既存データを保持し、旧Mac LaunchAgentを撤去した。
本番と開発は異なるデータベースのまま運用する。
開発でもメール送信・コード確認・公開Site URL・アプリコールバック・
12文字の最小パスワード長を設定済み。既存の登録済みアカウントは維持する。
