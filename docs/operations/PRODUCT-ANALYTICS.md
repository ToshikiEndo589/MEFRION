# MEFRION 利用分析

運営サイト `/console` の「MEFRIONの成長と使い心地」で確認する。閲覧・公式ストア数値の登録には既存の運営権限とMFAが必要。匿名・一般会員からの集計取得は禁止する。

## 指標と読み方

|指標|定義・注意点|
|---|---|
|端末DAU|日本時間の今日、利用中または起動を観測したインストール識別子の数。ゲストを含む|
|端末WAU / MAU|直近7日 / 30日間の同じ集計。人間の人数やAppleのアクティブ端末数と同一ではない|
|登録者DAU / WAU / MAU|上記の利用を、サーバーで認証確認できたアカウントIDごとに重複除去|
|現在の登録者|メール確認済み・未削除・非匿名・test_only以外の現在のアカウント数。過去累計ではない|
|日別の登録確認済み人数|現在存在するアカウントのメール確認日を集計。退会すると遡って減る|
|初回起動|この計測に対応したアプリから初めて観測した起動。実インストール日時や過去累計DL数ではない|
|セッション|初回または30分以上利用が途切れた後の復帰。1時間に複数回あり得る|
|時間別アクセス|日本時間の直近48時間。アプリ端末・起動回数・イベント数・共有リンク到着数を別々に表示。HTTP全リクエスト数ではない|
|D1 / D7 / D30継続率|初回観測日から正確に1 / 7 / 30日後に再利用した端末。判定対象日が終わるまで分母に入れない。期間内初回観測コホートのみ|
|初回利用ファネル|期間内の同じ端末について初回観測→登録確認→投稿受付の時刻順を確認。初回インストール時からの完全な追跡ではない|
|アルバム利用|開いた端末数と、期間中2日以上開いた端末数。保存は投稿画面の保存完了操作を数える|
|そっくり検索|検索開始・結果取得・失敗。成功は結果取得を意味し、ユーザーが似ていると感じたかは測定していない|
|画像・動画準備|ダウンロードや画像復号が終わるまでの時間と失敗。キャッシュヒットや実際の表示・再生開始は含まない|
|通信品質|固定分類の通信成功・失敗と中央値 / 95パーセンタイル。通信時間に認証再試行等の全体時間は含まない場合がある|
|投稿受付|公開申請RPCが成功したこと。運営による公開承認や画像アップロード全体の時間とは異なる|
|一般・運営投稿|公開中かつ対象期間に公開した投稿をDBから集計。一般投稿者は人間の認証アカウント単位|
|共有|Instagram / Xを開くボタンの操作。SNS投稿完了ではない。Xの共有文の固定リンクからApp Storeへ移る到着も別集計|
|バージョン別|自己申告されたアプリバージョンごとの観測端末と失敗イベント。同じ端末が更新前後に複数行へ入る|
|Apple公式数値|Apple Analytics Reports APIの標準レポートを毎日取得。手動転記は別枠。未取得は0に変換しない。Appleの日付を使用|

7 / 30 / 90日を切り替え、表ごとにCSVを取得できる。期間は日本時間で当日を含むカレンダー日。DAU/WAU/MAUと直近48時間だけは期間選択と独立する。

## 実装・個人情報

- iOS Releaseビルドのみ送信。Debug・UIテストの値は本番へ送らない。
- ランダムなインストールIDをアプリ内に保持し、DBにはSHA-256ハッシュを保存する。Apple IDFA・位置情報・広告用追跡は使わない。
- アカウント識別子は記録時点のアカウントと送信時の認証IDが一致するときだけ保存する。ログアウト後や別のアカウントに切り替えたキューを別人に付け替えない。
- 写真・動画本体、投稿本文、検索文、メール、パスワード、認証コード、生のURLをイベントに入れない。名前・区分はサーバーの固定許可リストに限る。バージョンは最大30文字。未知のキーは捨てる。
- イベント生データは90日で削除。インストールの初回/最終観測情報は90日間利用がなければ削除する。再インストール・OS復元・複数端末により同じ人の重複が発生し得る。
- 送信キュー最大200件、1回20件、10秒タイムアウト。送信失敗は次の利用時に再試行。同じイベントIDの再送は二重集計しない。オフライン中は発生日でなく受信日時に集計される。
- 全体20,000件/24時間、端末1,000件/時、生データ300,000件を目安に取り込みを制限する。最後のバッチ分だけ全体上限を超える場合がある。上限到達はダッシュボードに表示。アプリの本来の操作を失敗させない。
- クライアント計測は偽装可能。請求・売上・侵入判定には利用しない。セキュリティ監視の信頼できるサーバーイベントとは分離する。
- 新しい有料サービス・有料プランは契約しない。既存Supabase / VercelのDB・通信・実行量は増加する。規模拡大時は計測頻度、集約、保存期間を先に見直す。

## 公開・運用時に必要なこと

1. 新しいReleaseアプリを配布して初めてアプリ利用データが入る。既存配布版や過去の利用は遡って埋めない。
2. Apple API利用と継続レポートの生成を設定済み。通常のキーはSalesおよびReports。初回生成に用いた一時管理者キーは無効化済み。初回は1〜2日生成待ち。毎日05:30 JSTにVercel Cronで同期し、失敗時は固定の状態名で表示する。Appleのダウンロードは通常2日、インストールは通常5日まで改訂される。インストールはデータ共有に同意した利用者のみで、少人数では非表示。
3. App Store ConnectのAppプライバシー回答に識別子・製品操作・パフォーマンス情報の分析用途を反映する。PrivacyInfo.xcprivacyと公開プライバシーポリシーは更新したが、提出フォーム自体を更新済みとはしていない。
4. 新版で起動→登録→投稿→アルバム→そっくり→共有を行い、翌日の継続率分母を確認する。現時点のiOS Releaseはコンパイル検証、実測は配布後に確認する。

## 検証

- `supabase/tests/product_analytics.sql`: 匿名の取り込み、重複除去、未知キー非保存、不正イベント拒否、一般会員/匿名の権限境界、集計SQLをトランザクションで検証しロールバック。
- `sites/mefrion-info/scripts/product-analytics.test.mjs`: 空データ/未取得値、時間軸、上限警告、HTML文字列を実行しない描画、CSV式注入対策、共有リンクの固定遷移・ボット除外。
- GitHub CIは空DBへの全マイグレーション適用後にSQLテストも実行する。

## Apple自動連携の構成

- `analytics/apple.mjs` は5分のES256トークンでMEFRIONのONGOINGリクエストを読み、Downloads / Installations and Deletionsの標準レポートのみを選ぶ。公開アプリIDは6825337314に固定。詳細レポートは使わない。
- 初回の管理権限と日常の読み取り権限を分離。長期の管理者キー・SupabaseサービスキーはVercelへ置かない。4つの設定はVercelのProduction限定Secretとして保存。
- `/metrics/apple-sync` はProduction限定、64桁ランダム値のBearerを一定時間比較で確認。Vercel Cronが呼ぶ。DBの取り込みも同じ高エントロピートークンのハッシュ照合で保護し、公式数値以外の操作権限は持たせない。
- ページ送りはApple APIの同一オリジンだけ。ダウンロードはAppleドメインまたはAppleが返すASPのS3ホストに限定。Apple認証ヘッダーはダウンロード先に送らない。リダイレクトを拒否し、圧縮前後の容量とチェックサムを検証する。
- 同じ日付の古いprocessingDateは新しい値を上書きできない。同じinstance内のsegmentだけを合計し、異なる処理日の同じ日付は最新の値に置き換える。繰り返し実行しても加算しない。
- 1回の取得は各レポートの直近10instance、最大50segment / 160 API呼び出し。大きなレポートではbudget等を表示し、部分的な結果は保存しない。古い日付の例外的な訂正はこの取得範囲外になり得る。
- Apple原本・署名付きダウンロードURL・キーはダッシュボードや実行ログに出さない。日別の合計だけをDBに保存する。
- 参考: [Apple レポート取得](https://developer.apple.com/documentation/appstoreconnectapi/downloading-analytics-reports)、[データの完全性と訂正](https://developer.apple.com/documentation/analytics-reports/data-completeness-corrections)。
